# Ранг «Шаты» — версия 2

Решения команды, которые зафиксированы в этом документе:

1. **Одна лестница на весь мир.** Никаких отдельных лиг по школам и никаких «слоёв».
2. **Партии с ботами ранг не меняют никогда.** Бот — тренер без риска.
3. **Ранг не зависит от времени, проведённого в игре.** Объём партий не даёт очков.
4. Ничьи моделируются отдельно, иначе ранг сжимается.
5. Общий мировой ранг — главный; по режимам в профиле ведём статистику и отдельные числа.

Файлы: `rating/rank.js` (реализация), `rating/rank.test.mjs` (проверка),
`rating/rating_sim.py`, `rating/activity_sim.py` (симуляции), `rating_sim.png`, `rating_activity.png`.

## 0. Про «слои» — это была моя терминология, не устройство лиг

Слоями я называл **внутреннюю механику расчёта** (модель ничьих, шаг обновления, привязка
шкалы), а не разные таблицы и не разные лиги. Вы правы, что это путает: в продукте
**один мировой ранг и одна таблица**, и никаких сущностей вроде «слой 1 / слой 2» в
интерфейсе и в БД быть не должно. Ниже всё переписано без этой терминологии.

Заодно отпадает и калибровка на ботах, которую я предлагал раньше: раз боты не влияют
на ранг, привязку шкалы делаем иначе — **один общий пул на весь мир плюс нормировка
среднего**. Это даже надёжнее: сравнимость между школами получается автоматически,
потому что таблица одна.

## 1. Про юридическую часть (коротко)

- Формула Эло — математика, авторским правом **не охраняется**, брать её законно.
- Риск не в формуле, а в **бренде**: слово «ELO» — товарный знак в ряде классов, «Эло» — фамилия. Нельзя называть систему так и нельзя копировать визуал и тексты chess.com.
- **TrueSkill (Microsoft) запатентован** — не трогаем. Glicko, Glicko-2, OpenSkill — открытые.
- Значит: своё имя и своя формула — чисто по всем статьям. Что мы и делаем.

## 2. Чего не хватает у Эло (и почему мы делаем своё)

| № | Проблема | Проверено симуляцией |
|---|---|---|
| 1 | Ранг зависит от компании, а не от силы | один игрок (сила 1200) получил **1040** в слабом пуле и **1246** в сильном |
| 2 | Ничьи не моделируются → шкала сжимается | при 45% ничьих реальный разброс 235 → **134** (треть различий исчезла) |
| 3 | Зависимость от порядка партий | разброс **±14 пунктов**, до 80 между крайними |
| 4 | Объём игры раздувает число (если считать очки, а не оценку) | у Эло σ растёт с числом партий: **35 → 44** (см. §3) |
| 5 | Новичок выходит на уровень 55 партий, первые 20 — шум | 55 игр до +300 у классики |
| 6 | Дрейф шкалы | −6 пунктов за 12 сезонов и накапливается |
| 7 | Нет понятия уверенности | 1500 после 3 партий = 1500 после 300 |
| 8 | Ничего не говорит о тренировке | «зевнул ферзя» = «проиграл в равной борьбе» |

Ключевая мысль: **ранг должен быть оценкой силы, а не копилкой заслуг.** Оценка сходится
к правде с числом партий, копилка растёт от количества. Это различие — вся суть §3.

## 3. Требование «ранг не как кубки в Brawl Stars»

Проблема кубковой модели: +8 за победу, −4 за поражение. Играешь много и с более слабыми —
число растёт бесконечно: **+1900 очков за 500 партий**, +19 000 за 5 000. Это не сила,
это стаж.

Как это ломается у нас:

**Формула шага обновления:**

```
K = K_min + (K_max − K_min) / (1 + n / 8)        // n — число рейтинговых партий
K_max = 48 (новичок), K_min = 6 (устоявшийся)
Δ = K · (S − E),   S = 1 / 0.5 / 0,  E = ожидаемый счёт
```

Что это даёт на практике (симуляция: 200–400 игроков одинаковой силы, все играют с равными):

| Число партий | Разброс ранга, классический Эло (K=20) | Наш «Шаты» (K ~ 1/n) |
|---|---|---|
| 50 | ±34 | ±35 |
| 500 | ±40 | **±16** |
| 5 000 | ±44 | **±6** |

То есть у нас **чем больше играешь, тем точнее число, и оно всё ближе к правде** —
а не всё выше. У человека, который сыграл 500 партий с равными, ранг остаётся тем же.
Проверено и в коде: 2000 партий против равных → **ровно 1000 шатов**, с чего начинали.

Дополнительные правила против «времени в игре»:
- **Боты и товарищеские партии — вес 0.** Победа над ботом не даёт ничего.
- **Лимит 25 рейтинговых партий в сутки.** Дальше играешь, но без ранга (защита от накрутки за ночь).
- **Максимум 3 партии с одним и тем же соперником в сутки** идут в ранг (защита от договорных партий и «фарма друга»).
- **До 10 рейтинговых партий** игрок в статусе «калибровка»: ранг виден, места в таблице нет.
- **За бездействие ранг не отнимаем.** Каникулы и болезнь — не наказание. Вместо этого в профиле метка «давно не играл» и серия активности — но это не влияет на разряд.
- Отдельно есть **опыт/уровень аккаунта** (косметика, ачивки) — он может расти от активности. Ранг — нет. Это и есть разделение «прогресс» и «сила».

## 4. Единицы и числа: как называется и что значит

**Единица ранга — «шат»** (множественное — «шаты»), формально «очко ранга» (ОШ).
Короткое, своё, не пересекается с «Эло» и «кубками», легко произносится детьми:
«у меня 1 250 шатов».

**Шкала:** 0–2 600, старт 1000, шкала 400 (как принято в логистических моделях).
Разница в 400 шатов ≈ 10:1 по шансам.

**Что означает разница** (с учётом ничьих, ν = 0.9):

| Разница | Победа сильного | Ничья | Победа слабого |
|---|---|---|---|
| 100 шатов | 45% | 30% | 25% |
| 200 шатов | 55% | 28% | 17% |
| 400 шатов | 72% | 21% | 7% |

**Лестница разрядов** (то, что видит ребёнок):

| Шаты | Разряд | Кто это примерно |
|---|---|---|
| 0–800 | Новичок | знает правила, ещё зевает фигуры |
| 800–1000 | Юный шахматист | играет осознанно, видит простые тактики |
| 1000–1200 | 4-й разряд | уверенно держит партию, знает маты в 1–2 хода |
| 1200–1400 | 3-й разряд | считает на 2–3 хода, не теряет фигуры «на пустом месте» |
| 1400–1600 | 2-й разряд | базовая стратегия, играет дебюты осмысленно |
| 1600–1850 | 1-й разряд | уровень школьной сборной, городские турниры |
| 1850–2100 | Кандидат | призёр городских и областных турниров |
| 2100+ | Мастер школы | сильнейшие ученики, уровень КМС-подступа |

Повышение — при `порог + 40`, понижение — при `порог − 80` (гистерезис: разряд не мигает
на границе вчера «дал», сегодня «забрал»).

### Ответ на ваш пример: «если там 1200 Эло, у нас сколько?»

**Числа совпадают: 1200 Эло ≈ 1200 шатов.** Это сделано намеренно — шкала та же
(400 на десятикратные шансы), поэтому тренеру не надо пересчитывать в голове,
а дети не теряются.

Но смысл разный, и это важнее совпадения чисел:
- **1200 шатов** — это «3-й разряд», посчитанный по **одной мировой таблице**, куда идут только партии с живыми людьми и где среднее не уезжает;
- **1200 Эло** — это «столько, сколько получилось в твоей компании»: в слабой школе то же умение даёт 1040, в сильной — 1246.

Так что ответ такой: **не 2000 очков и не 2000 шатов, а те же ~1200 шатов** — но если
вы хотите, чтобы число выглядело «своим», можно поставить множитель (например, 1.5 →
1200 Эло ≈ 1800 шатов: тогда лестница 0–3900, а разница 600 = 400 «настоящих»).
Я бы **не умножал**: лишняя арифметика ради непохожести, а непохожесть у нас уже есть
в названии, разрядах и правилах.

## 5. Режимы: одна лестница + отдельные числа в профиле

Как решили: **общий ранг один**, но в профиле видно, сколько и как играешь в каждом режиме.

| Режим | Идёт в мировой ранг? | Вес | Что показываем в профиле |
|---|---|---|---|
| Классика (30+ мин) | да | 1.0 | партии, победы, отдельное число |
| Рапид (10–15 мин) | да | 1.0 | партии, победы, отдельное число |
| Блиц (3–5 мин) | да | 0.85 | партии, победы, отдельное число |
| Пуля (1–2 мин) | да | 0.6 | партии, победы, отдельное число |
| С ботом | **нет** | 0 | партии, лучший уровень бота, «тренер» |
| Товарищеская | **нет** | 0 | партии |
| Задачи | нет | — | решено задач, серия |

Почему вес, а не «каждому режиму своя лига»: если пуля и классика — разные лиги, ребёнок
выбирает самую выгодную и мировой ранг перестаёт что-то значить. Вес решает это:
пуля даёт 60% обычного шага, поэтому «набить» ранг пулей нельзя, а играть в неё не запрещено.
Отдельные числа по режимам остаются **внутри профиля как справка** — они не меняют разряд.

Правило отображения: разряд считается **только от мирового ранга**. Если ребёнок играет
только блиц, у него просто мало классических партий — это видно в профиле и не мешает рангу.

## 6. Кланы (не отдельная лестница, а витрина)

Кланы не создают второй ранг игрока. Есть одна витрина «Кланы мира», где место клана
считается от **мирового ранга его участников**:

```
рейтинг клана = среднее по 5 сильнейшим участникам,
                у которых есть минимум 3 рейтинговые партии за 30 дней
```

Почему топ-5, а не все: иначе выигрывает самый большой клан, а не самый сильный. Почему
требование активности: иначе клан из пяти «законсервированных» сильных висит в топе вечно.

## 7. Формулы целиком

```
γa = 10^(Ra/400),  γb = 10^(Rb/400)
D  = γa + γb + ν·√(γa·γb)                          // ν = 0.9 — склонность к ничьим
P(победа A) = γa/D,  P(ничья) = ν·√(γa·γb)/D,  P(победа B) = γb/D

E  = P(победа A) + 0.5·P(ничья)
K  = 6 + 42/(1 + n/8)
Ra' = Ra + w_режима · K · (S − E)     // S: 1 победа, 0.5 ничья, 0 поражение
```

Нормировка мира (раз в сутки, по активным игрокам):

```
shift = mean(R) − 1000;   R' = max(200, R − shift)
```

Проверка реализации: `node rating/rank.test.mjs`.

## 8. Хранение в Supabase

```sql
alter table profiles
  add column rating          numeric(7,1) not null default 1000,  -- мировой ранг, шаты
  add column rated_games     int not null default 0,              -- n для K
  add column division_id     text not null default 'novice',
  add column division_peak   text not null default 'novice',      -- лучший разряд не отнимаем
  add column placement_done  boolean not null default false;      -- 10 партий

-- отдельные числа по режимам: только справка для профиля
create table player_modes (
  profile_id   uuid references profiles(id) on delete cascade,
  mode         text not null,        -- classic | rapid | blitz | bullet | bot | friendly
  rating       numeric(7,1) not null default 1000,
  games int not null default 0,
  wins  int not null default 0,
  draws int not null default 0,
  losses int not null default 0,
  primary key (profile_id, mode)
);

-- история для графиков прогресса и разбора
create table rating_history (
  id bigserial primary key,
  profile_id uuid references profiles(id) on delete cascade,
  game_id uuid,
  mode text not null,
  rating_before numeric(7,1), rating_after numeric(7,1), delta numeric(6,1),
  created_at timestamptz not null default now()
);

-- защита от накрутки: считаем партии за сутки одним запросом
create or replace view rated_today as
select profile_id, count(*) as games, 
       max(count(*)) over (partition by profile_id) as dummy
from rating_history
where created_at > date_trunc('day', now())
  and delta <> 0
group by profile_id;

-- витрина кланов
create or replace view clan_ratings as
select c.id as clan_id, coalesce(round(avg(x.rating)::numeric,1),0) as clan_rating,
       count(x.profile_id) as counted_members
from clans c
left join lateral (
  select cm.profile_id, p.rating
  from clan_members cm join profiles p on p.id = cm.profile_id
  where cm.clan_id = c.id
    and p.rating_updated_at > now() - interval '30 days'
  order by p.rating desc limit 5
) x on true
group by c.id;
```

**Ранг пересчитывается только на сервере** (Supabase Edge Function или API-роут) после
фиксации результата партии. На клиенте — только отображение.
